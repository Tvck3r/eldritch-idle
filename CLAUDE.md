# The Summoning — notes for Claude

An incremental/idle game: vanilla JS (ES modules) + Vite, no UI framework. Live at
https://tvck3r.github.io/eldritch-idle/. Plans, priorities and the **player feedback log** are in
`ROADMAP.md`. **Read it first.**

## Commands

- `pnpm dev`: Vite dev server at http://localhost:5173 (also on your LAN, so you can open it on a phone)
- `pnpm test`: Vitest (core logic). `pnpm test:watch` while working.
- `pnpm build` / `pnpm preview`: production build to `dist/`, served at :4173
- `pnpm check`: tests + build (what CI runs)
- Push to `main` → CI (test, build) → deploy `dist/` to GitHub Pages. PRs run test + build only.

## Architecture (`src/`)

```
core/        game rules. NO DOM: must run in Node (tests).
  constants.js     tuning numbers (veil goal, sanity, act thresholds…)
  content.js       Act I data: followers, milestones, rites, pacts, madness events, questions,
                   apparitions, buffs, omens, story beats, lore
  content-acts.js  Acts II–III data: sigils, mutations, trials, seals, endings, revelations
  cosmetics.js     vessel wardrobe data + unlock rules
  state.js         freshState(), PERSIST / AWAKEN_RESET / NG_KEEP, `state` (live binding), setState(), fx, runtime
  economy.js       a run's rules: modifiers() pipeline, production, costs, buying, sanity, madness + questions,
                   apparitions, buffs, progress checks (omens/story/revelations/trials), automation, tick(), catchUp()
  prestige.js      layers: summon (Favor), awaken (Elder Signs), sigils, mutations, trials, seals, endings, NG+, depths
  save.js          versioned envelope (v3), MIGRATIONS, load/save, export/import
  settings.js      player prefs (separate storage key from the save)
  events.js        tiny bus: 'log', 'summoned', 'awakened', 'state-replaced', 'settings', 'choice', 'apparition',
                   'caught', 'revelation', 'finale', 'ending', 'tab'…
  format.js        number formatting
ui/          DOM: render.js (every tick), shell.js (tabs, collapsing scene, omen feed), chant.js (tap/hold),
             inspect.js (hover tooltips + touch sheet; registerTip/registerAction), acts.js (Ritual/Rites sections
             for questions, awakening, trials, seals, sigils, mutations, automation), apparitions.js (tap targets, buff chips),
             audio.js (WebAudio), ending.js (finale + closing sequence), vessel-panel.js (wardrobe + revelations),
             grimoire.js, modal.js, settings-panel.js, intro.js
scene/       canvas: scene.js (320×100, pixelated; every layer incl. acts and endings), vessel.js (avatar), sprites.js
public/      manifest, icons (generated by scripts/make-icons.mjs), sw.js (service worker)
scripts/     make-icons.mjs, simulate.mjs (balance bot: `node scripts/simulate.mjs active|idle [hours]`)
admin.js     dev cheats (` key or ?admin), including act shortcuts (apparition, question, awaken, seals, finale)
main.js      boot: load settings + save, init UI, game loop, service worker
```

Rules of the road:
- **Add content by adding data** to `content.js` / `cosmetics.js`; avoid special-casing in logic.
- **core never touches the DOM.** Announce via `emit('log', msg)` and friends; ui subscribes with `on(...)`.
- `state` is an ES live binding. Mutate fields freely, but replace it wholesale only via `setState()`
  (which emits `state-replaced`, so the UI rebuilds its lists).
- Keys that survive a summoning are in `PERSIST` (state.js); an Awakening also drops `AWAKEN_RESET`; New Game+ keeps only `NG_KEEP`.
- **Every bonus goes through `modifiers()`** (economy.js). Content supplies `apply(m, s)` functions that multiply fields
  of `m` (`all`, `click`, `gen[id]`, `drain`, `madMax`, `favorGain`…). Don't compute bonuses anywhere else.
- **Balance changes:** run `node scripts/simulate.mjs active 20` before and after and compare the milestone times
  (target: first summon ≈ 1h, first Awakening ≈ 4h, Act III ≈ 7h, ending ≈ 10–12h).
- **Changing the save shape?** Bump `SAVE_VERSION` in `save.js`, add `MIGRATIONS[old]`, and add a test in `save.test.js`.
  Nested objects that gain fields also need a merge line in `normalize()`.
- Inspection: add `data-tip="key"` and a tip via `registerTip(name, fn)` (or `TIPS` in ui/inspect.js); an optional
  `registerAction` adds a buy button to the touch sheet. Elements that need it must not be `disabled` (use `.cant`).
  List rows are `<button class="row">` with an `.info` side (inspect on touch) and a `.buy` side (acts); use `rowHtml()`.
- Anything visual must respect `settings.reducedMotion` (scene: no shake, glitch or full flash; CSS: `body.reduced-motion`).
- Tests live next to the code as `src/core/*.test.js`. Write tests for new rules.

## Testing visually (Windows, headless Edge)

- Serve a real build: `pnpm build && pnpm preview` (run it in the background), then
  `msedge --headless=new --screenshot=out.png --window-size=W,H --virtual-time-budget=2500 "http://localhost:4173/..."`
- **Set up game state with a URL:** generate a save in Node with the real core modules
  (`setState(...)`, then `encodeURIComponent(exportSave())`), and open `/?admin=0&save=<that>`.
  `?admin=0` keeps the cheat panel closed.
- **Phone widths:** headless Edge won't lay out narrower than ~477px. Put a page in `dist/` (gitignored, same origin)
  that loads the game in `<iframe width="390">`. Being same-origin, it can also *drive* the game
  (`iframe.contentWindow.document...click()`) and print results.
- **CSS animations freeze under `--virtual-time-budget`** and `animationend` never fires, so check animation-driven
  logic with `--dump-dom` or via the harness, not by eye. Add `body.reduced-motion` in the harness to see sheets/overlays
  in their final state. The scene clock uses `performance.now()`, which does advance under virtual time.
- Synthetic touch: dispatch `new PointerEvent('pointerdown', { pointerType: 'touch', bubbles: true })` then `.click()`.

## Conventions

- pnpm only. Conventional commits with scope, e.g. `feat(mobile):`, `fix(core):`, `chore(ci):`.
- Work on a branch and open a PR. `main` deploys straight to the live site.
- Mobile-first: anything new must work at 390px with touch. Layout breakpoint: `min-width: 900px` is the desktop
  two-column shell (`isWide` in ui/dom.js); `(hover: none)` means touch inspection.
- Editing on Windows: Python's default encoding is cp1252 and it writes CRLF. Use `io.open(..., encoding='utf-8', newline='')`,
  or the Edit tool. Never run line-ending fixes over binary files (the PNG icons).
- Voice: UI copy is in-world and ominous, but mechanics text stays plain and exact.
